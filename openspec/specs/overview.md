# AwesomeClaude 系统总览

## 一句话定位

AwesomeClaude 是一个类 Claude Code 的 AI Agent 框架：常驻的 Core 守护进程承载对话与工具编排能力，轻量的 Client 只负责交互与呈现，二者通过统一的远程调用协议解耦。

## 系统形态

采用 Client-Server 架构：

- **Core（守护进程）**：常驻后台，负责接入连接、理解请求、驱动 LLM 与工具、管理会话与任务。
- **Client（命令行）**：面向用户，负责采集输入、发起请求、实时渲染流式输出。
- **协议层**：两者唯一的通信契约，基于 TCP 的行式消息传输，遵循 JSON-RPC 2.0（请求 / 响应 / 通知 / 错误）。

```
用户 ──> Client（交互/渲染）
            │  请求、响应、实时通知
            ▼
      协议层（消息契约）
            │
            ▼
        Core 守护进程
        ├─ 接入与路由
        ├─ 会话管理
        ├─ Agent 编排 ──> LLM 抽象 ──> 外部大模型
        │        └────> 工具系统
        └─ 任务追踪 / 日志
```

## 核心模块

### 1. 客户端交互
采集用户输入、识别本地命令、发起远程调用，并把服务端返回的响应与实时通知渲染成可读的流式输出与用量摘要。支持指定会话标识以加入共享会话。

### 2. 协议与传输
定义 Client 与 Core 之间唯一允许的通信契约：消息的编解码、分帧、方法名与参数/返回结构、错误码。网络通信全程异步，保证不阻塞。

### 3. 服务端接入与路由
监听连接、按行接收并解析消息、将请求分发到对应业务处理器，再把结果回写。支持多客户端并发与优雅退出。

### 4. 会话管理
维护会话到订阅连接的映射与对话历史。多个客户端可订阅同一会话，实时共享同一段对话；新加入者可回放历史。用户输入与 AI 输出会在会话内广播（输入排除发起方）。

### 5. Agent 运行时
系统的编排核心。接收一条用户消息后，反复执行"调用大模型 → 若模型要求使用工具则执行工具 → 把工具结果回填继续推理"的多轮循环，直至得到最终答复或达到步数上限。负责把过程中的文本增量、思考、工具调用等事件透出给上层用于推送与记录。

### 6. 工具系统
提供统一的工具注册、查询与执行入口，并定义工具运行上下文。内置工具当前覆盖时间查询与受沙箱约束的文件操作；沙箱保证路径不越出工作区、限制单次读写体量、只处理文本内容。未来命令执行等能力在此扩展。

### 7. LLM 抽象
以供应商无关的接口封装大模型调用，当前实现基于 Anthropic 兼容协议，支持流式文本、思考与工具调用事件，并把认证、超时、限流等异常映射为统一的错误类型。

### 8. 任务追踪
为每次对话生成唯一任务标识，按阶段记录完整生命周期（创建、上下文构建、每轮调用、工具执行、完成/失败/中断），并区分多轮轮次。记录持久化为可追溯的结构化事件流。

### 9. 可观测性
提供双通道结构化日志（终端彩色文本 + 文件 JSON），与任务事件流共同构成运行时可观测面。

## 关键交互流程

一次对话请求：用户输入 → 客户端发起远程调用 → 服务端建任务并构建上下文 → Agent 运行时分多轮驱动模型与工具 → 期间持续向客户端推送流式文本与工具进度通知 → 结束时回传最终结果与用量 → 客户端渲染摘要。

共享会话场景：客户端先订阅会话（回放历史）→ 发起对话 → 结果实时广播给会话内所有订阅者 → 对话历史被记录，供后续加入者回放。

## 设计约束

- Client 与 Core 只通过协议层通信，禁止相互直接依赖。
- 网络 I/O 全异步，守护进程须支持优雅退出。
- 配置一律来自环境变量，不硬编码敏感信息。
- 文件工具默认在受限工作区内运行。
- 模块边界随迭代演进，结构可随能力扩展而调整。

## 当前阶段

已完成基础链路、流式对话、任务生命周期与多客户端会话共享；工具调用（Agent 循环 + 文件沙箱）已部分落地。后续将扩展命令执行、记忆压缩、任务规划与更多客户端形态。
